# BetterDisplay Free and Pro

## What the current product covers

### Takeaway

BetterDisplay is a benchmark for three different jobs: controlling physical monitors, managing the macOS desktop layout and rendering modes, and creating or presenting virtual desktops. Most routine device controls are free. Pro concentrates on flexible scaling, protected configurations, high-end brightness and image processing, and streaming. [Official tier comparison](https://betterdisplay.pro/guide/licensing/free-and-pro-features/)

### Cited Findings

- **Version baseline.** GitHub marks v5.2.1 as latest stable and v5.3.2 as a prerelease. BetterDisplay 5 supports both Apple silicon and Intel and requires macOS 26.3 or later. The live feature guide also describes prerelease additions such as touch menus, interactive Dynamic Island/Live Activity OSD, Color Profile Retouch, experimental LUT-to-ICC conversion and compatible MacBook logo lighting. Identify those as prerelease when benchmarking stable. The project links older versions for Ventura, Sonoma, Sequoia and earlier macOS versions. - **Free hardware control.** Supported DDC connections expose brightness, contrast, volume, RGB gain, inputs, backlight/power, auto-configuration, per-display input labels, command mappings for predefined controls and communication tweaks. Some DisplayLink setups support DDC/colors. Optional device integrations include HDMI-CEC and network controls for supported LG webOS, Samsung Tizen and Philips Android TVs plus Yamaha AVRs, with floating remotes; the expanded Yamaha remote is noted in the prerelease. ### Inferences

- Physical monitor control, macOS mode/arrangement, optional capture and private/system override functions are separate implementation and test scopes. BetterDisplay's competitor tier should inform expected jobs, with no implication for MacMonitorControl licensing.
- Strong opening release candidates are hardware brightness/contrast/volume, a clearly indicated software dimming fallback, existing mode selection, display identification, keyboard support and predictable recovery. A compelling next benchmark is named configuration restore, with confidence based on connected displays and available modes.

### Gaps

- Public product documentation establishes advertised behavior and limitations. It does not define an Apple-supported or forward-compatible API for every advanced feature.

## What limits availability and safe recovery

### Takeaway

The Mac model, OS, display firmware and entire connection path determine access independently for each control. Build and test for distinct capability states rather than a single compatible-monitor flag. [DDC guide](https://betterdisplay.pro/guide/interface-reference/settings/displays/display/device-control/ddc/) · [Tier comparison availability](https://betterdisplay.pro/guide/licensing/free-and-pro-features/#availability-notes)

### Cited Findings

- DDC may work for writes without readback, a slider can differ from raw monitor values, and some docks/adapters fail to pass DDC at all. Input values and power actions vary, and manual power-on may be required. CEC separately needs compatible Apple silicon HDMI hardware and a CEC-capable sink. [DDC guide](https://betterdisplay.pro/guide/interface-reference/settings/displays/display/device-control/ddc/) · [Connection controls](https://betterdisplay.pro/guide/interface-reference/app-menu/device-menu/header-and-connection/) · [Tier comparison availability](https://betterdisplay.pro/guide/licensing/free-and-pro-features/#availability-notes)
- Custom/flexible scaling relies on eligible built-in/native connections and may require activation or restart; available modes depend on GPU, OS and link. Virtual mirror creates a shared desktop, whereas streaming captures a separate source and needs Screen Recording permission. Changing mode, mirror or stream can affect main-display status and routing. [HiDPI guide](https://betterdisplay.pro/guide/tutorials/fully-scalable-hidpi-desktop/) · [Streaming guide](https://betterdisplay.pro/guide/interface-reference/app-menu/device-menu/streaming/)
- BetterDisplay guards the last functional physical display and tries to recover if no eligible one remains. Apple silicon soft disconnect typically requests standby, while Intel has caveats including temporary loss of all usable display output until restart. Protection suspends if it detects repeated reconfiguration loops. [Connection safety](https://betterdisplay.pro/guide/interface-reference/app-menu/device-menu/header-and-connection/) · [Protection behavior](https://betterdisplay.pro/guide/interface-reference/app-menu/device-menu/configuration-protection/)
- Color-table HDR boost is Apple-silicon-only; Metal can be available on Intel and Apple silicon; experimental direct boost requires compatible built-in Apple silicon XDR hardware. Panel calibration must be checked on physical output and cannot be verified by screenshot. External displays need suitable HDR mode. [XDR/HDR guide](https://betterdisplay.pro/guide/tutorials/xdr-and-hdr-brightness-upscaling/)
- Apple silicon's temporary EDID application and Intel's model-level override differ. Applying an override can blank the screen or change observed identity; permanent device writes can make hardware unusable. [EDID guide](https://betterdisplay.pro/guide/interface-reference/settings/displays/display/edid/)

### Inferences

- Build per-capability diagnostics, retain a distinguishable last commanded vs observed value, and re-test display membership across wake, hotplug and multiple identical units. A reversible mode preview, refusal to lose the last usable screen, and a recovery path outside the affected display are core requirements for automated topology changes.
- Defer permanent EDID device writes unless explicitly approved as a project requirement and validated with expendable devices. Prototype flexible scaling, virtual screen creation, extra HDR, and soft disconnect independently.

### Gaps

- Vendor claims were not verified on local Mac/display combinations. Behavior with specific docks, USB and HDMI adapters, DisplayLink, wireless/Sidecar, multiple identical displays, capture overhead, and macOS upgrades needs a hardware test matrix.
